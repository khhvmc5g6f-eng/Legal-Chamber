# Honest Status

Legal Chambers' own governing rule (`docs/OPERATING_RULES.md`, Part I) forbids fabricating legal authority. This file exists so that rule applies to the repository's own marketing, not just its output. Read this before trusting anything else in the repo about "what Legal Chambers can do."

## Live seven-matter stress test (2026-08-22)

After the review pass below, a further Workflow-orchestrated stress test actually ran the repository - 6 seeded hard-safety hallucination traps plus 7 simulated legal matters (employment tribunal, judicial review, US federal litigation, Australian contract dispute, French/EU regulatory, NZ appeal, academic assessment), each executed by real agents reading and following the actual skill/agent files, not described. Full results: `LEGAL_CHAMBERS_STRESS_TEST_REPORT.md`, `DEFECT_REGISTER.md`, `LEGAL_CHAMBERS_COVERAGE_MATRIX.md`.

**Unresolved observation, noted rather than silently dropped**: `matters/M1-KESTREL/final/case_theory_memo.md` (written before the D-04 fix to `agents/solicitors/ROLE.md` was committed, confirmed by file mtimes) nonetheless describes "authority-weight discipline applied per `agents/solicitors/ROLE.md`" and references "a prior stress test" catching that exact failure mode - language that could not have been literally true of the file's content at the moment it was written. This is either a striking coincidence (the agent independently arrived at the same fix and mis-attributed it), or an instance of an agent asserting a source-backed claim that doesn't actually check out against the file it names - precisely the class of problem this whole project exists to catch, here appearing in the system's own self-generated commentary rather than in a legal citation. Not fully diagnosed in this pass; recorded honestly rather than resolved with confidence it doesn't have.

Headline: 13/13 seeded fabrication traps caught, zero cross-matter data leakage, the simulated judiciary ruled against the user in 2 of 7 matters (not sycophantic), and the five-hearing moot showed genuine round-to-round evolution. Twelve real defects were found and fixed, the most significant being that **none of the 13 agent roles in `agents/*/ROLE.md` had `Write` access** despite being designed to persist ledgers and case documents - the structural reason several matters had a stage claim an output that didn't actually exist on disk. Also fixed: a missing EU-level jurisdiction pack (country packs alone can't answer an EU-law question), a chronology schema that couldn't record an event with a genuinely unknown date, no gating on conflict-check clearance or confirming which party is the user's side before substantive work proceeds, and a new deterministic cross-reference checker (`scripts/verify_matter_refs.py`) to catch dangling fact/evidence/chronology IDs.

**Update (`0.1.4`-`0.1.5`)**: the Write-access fix has since been independently confirmed by two fresh live agent runs (solicitor role and judiciary role, no cached context reused) - both produced real, schema-valid files, each re-verified by the agent itself and again by this repository's own deterministic scripts. A persistence-vs-claim checker (`scripts/verify_matter_persistence.py`), a style audit of the stress test's own generated drafts (`STYLE_AUDIT_REPORT.md`, which found and fixed a real gap: the no-em-dash rule was never actually checked by a linter that already existed), the first real regulator profile (`regulators/cnil.md`), the first populated example (`examples/employment-tribunal-full-chambers/`), and a working CLI (`bin/legal` / `scripts/legal_cli.py`) were all added. Current release classification: `BETA` - see `LEGAL_CHAMBERS_STRESS_TEST_REPORT.md`'s "Release Classification" for the reasoning as of that version. This note describes the `0.1.4`-`0.1.5` snapshot specifically; both gaps it names have since been closed as of later versions - `scripts/legal_api.py` (a real programmatic API, `0.1.6`) and a populated Authority Graph in two jurisdictions (US-Federal since `0.1.6`, England & Wales added `0.1.7`, see "What is real in this build" below) - kept here rather than silently deleted so the version history stays legible.

## Independent review pass (2026-08-22)

Before this build was pushed, five independent review agents (a judge-lens read of the adversarial workflow, a solicitor-lens read of the practice skills, a paralegal-lens read of the operational schemas, a live fact-check of all 8 jurisdiction packs against WebSearch results, and a technical/code review of the scripts, schemas, and CI) were run against the actual files on disk, not against a description of them. This found and led to fixing:

- **One confirmed factual error**: `jurisdictions/australia/README.md` named "Family Court of Australia" as an extant standalone court; it merged into the Federal Circuit and Family Court of Australia (FCFCOA) on 1 September 2021. Corrected.
- **One refinement** to `jurisdictions/scotland/README.md`'s court diagram (Outer House and Sheriff Court are parallel first-instance tracks, not sequential tiers - the original wasn't wrong exactly, but was more linear than reality).
- **Three real regex bugs in `scripts/citation_lint.py`**: the US reporter pattern couldn't match `F.2d`/`F.3d`/`F. Supp. 2d`-style citations (the most common US federal citation shape), the UK neutral-citation pattern couldn't match two-word court codes like `EWCA Civ`/`EWCA Crim`, and the fenced-code-block stripper mismatched nested backtick fences of different lengths. All three fixed and verified against the exact failing examples the review supplied.
- **Dead code** in `citation_lint.py` (`STOCK_PHRASES` was defined but never actually consulted - the real, separately-maintained `STOCK_REGEXES` list could silently drift from it) - unified into one source list.
- **A real gap in `scripts/deadline_calculator.py`**: calendar-day deadlines never rolled off a weekend/holiday even though many real procedural rules require that. Added `--roll-if-non-business` as an explicit opt-in (never a default, since whether to roll is itself jurisdiction-specific), and expanded the selftest from 4 to 10 cases to cover `--inclusive-of-trigger`, `days=0`, negative days, and the new roll behaviour, none of which had a test before.
- **The most serious structural finding**: `workflows/five-hearing-adversarial.md` asserted "hearing memory" (each hearing builds on the last) with no schema or file location backing it - given the isolated-context independence rule in `AGENTS.md`, there was no actual channel for that to happen. Added `schemas/hearing.schema.json` and rewrote the workflow so each hearing reads the prior hearings' records before starting. Also fixed a sequencing error (costs were being assessed in Hearing 4, before the Hearing 5 merits disposition existed to base them on - costs now follow Hearing 5, matching how costs are actually decided in practice) and added an explicit note that this workflow does not model interim applications, disclosure timing, or case management conferences (a real gap, not silently glossed over).
- **Operational gaps a practising solicitor and a paralegal both independently flagged**: no day-one limitation check ahead of the general case-killer sweep, no client-care/costs-information step, no pre-action-protocol/ADR gate, no without-prejudice drafting discipline, no expert-evidence workflow, no chronology schema at all despite chronology being the most-described-but-least-supported workflow in the build, and no disclosure/bundle fields on the evidence record. Addressed: `skills/legal-litigation/SKILL.md` gained a "day-one triage" step before the issue tree, `skills/legal-draft/SKILL.md` gained a correspondence-register step, `schemas/chronology.schema.json` and `docs/ID_CONVENTIONS.md` were added, `schemas/evidence.schema.json` gained a `disclosure` object and `family`/`version_of` linking, `schemas/fact.schema.json` gained `date_certainty` and a chronology cross-reference, and `workflows/disclosure-register.md` documents how they fit together.

Not fixed, and tracked as open gaps rather than glossed over: a full interim-application/case-management engine, a full expert-instruction workflow beyond the one-paragraph note now in `legal-litigation/SKILL.md`, and automated (rather than manual) disclosure/relevance review. See the roadmap below.

## What is real in this build (current version: see `CHANGELOG.md` for the full version history)

- **The router and skill architecture.** `skills/legal-work/SKILL.md` genuinely classifies matter type, resolves jurisdiction (by asking, no geolocation or auto-detection is implemented anywhere in this repo), and loads only the specialist skill and jurisdiction pack a task needs.
- **The ledger and schema design.** `schemas/*.schema.json` are real, usable JSON Schemas for facts, evidence, authorities, issues, deadlines, matters, drafts, and prospects. They encode the status vocabularies (`ESTABLISHED`, `DISPUTED`, `UNVERIFIED`, etc.) from the spec.
- **The quality gates.** `docs/QUALITY_GATES.md` is a real checklist a matter must pass before any document may be marked `VERIFIED FOR FILING`, and that final state can only be set by a human reviewer, never by the skill itself (enforced by convention here, since this is a prompt-based system with no execution sandbox to hard-enforce it).
- **The deterministic scripts.** `scripts/deadline_calculator.py`, `scripts/citation_lint.py`, and `scripts/style_fix.py` are real, dependency-free Python that do arithmetic and pattern matching, not LLM guesses, for the narrow things they cover (business-day deadline math, citation-shape linting, and same-grammatical-slot stock-phrase replacement respectively). They are intentionally narrow; see their own docstrings for exact coverage. `citation_lint.py` covers UK neutral citations (with division/chamber suffix), UK OSCOLA law-report and statute citations, EU case numbers, ECLI identifiers (EU/France/Spain), and US reporter citations - the last additionally checked against a real, vendored table of ~1,340 known US reporter abbreviations (`scripts/data/reporters.json`, Free Law Project's reporters-db, BSD-2-Clause) rather than shape alone, still with zero pip dependencies. `style_fix.py` fixes only what it can prove is safe (never a quotation, code block, em dash, or hedged/absolute claim) - it is a plain-language drafting aid, not an AI-detector-evasion tool, and makes no claim about detector output; see `docs/STYLE_GUIDE.md`'s "What this repo will not build."
- **A practice-area taxonomy.** `docs/PRACTICE_AREAS.md` (~99 named fields) and `schemas/matter.schema.json`'s new `practice_areas` field give the router a substantive-subject axis distinct from `matter_type`'s process axis. Classification metadata only - it doesn't assert what any field of law actually says, and isn't a substitute for the verification steps above. That same file's "Coverage status" section is the authoritative, honest count of how much of the taxonomy actually has real content: 94 of the 99 areas, all narrow, one or two doctrinal points each - England & Wales's own taxonomy coverage is now complete (all 99 areas have real content or an honestly-documented reason they don't) - not the "full legal suite" a bare list of 99 names could be mistaken for.
- **The US Federal jurisdiction pack's connector story.** This session has a live CourtListener MCP connector. `jurisdictions/us-federal/README.md`'s "Live verification capability" section documents how to use it to pull real case metadata for a specific matter. That is a genuine, checkable capability, not a claim about training-data recall.
- **Court hierarchy and citation-style structure for all 8 seeded jurisdictions.** England & Wales, Scotland, US Federal, Australia, Canada, New Zealand, Spain, and France each have a pack recording their court hierarchy, authority-precedence rules, and citation style conventions. This is stable, well-documented public information about how each legal system is structured (e.g. "the UK Supreme Court sits above the Court of Appeal," "France is a civil-law jurisdiction using the Cour de cassation as its highest ordinary court," "OSCOLA is the standard UK academic/legal citation style"). It was written from general legal knowledge, not fabricated case-by-case, and it does **not** include any specific case citation, statutory pinpoint, or procedural deadline as verified fact. **England & Wales's court hierarchy and citation-style claims were promoted to `COMMUNITY_REVIEWED`** on 2026-08-23 after being independently checked live against `judiciary.uk`'s official court-structure page and `law.ox.ac.uk/oscola` - the first jurisdiction pack in this repository to move off `STRUCTURAL_DRAFT` for its structural narrative specifically (its Authority Graph content was already separately verified). The other seven jurisdiction packs' structural narratives remain `STRUCTURAL_DRAFT` - nobody has yet run the same live-check exercise against them.

## Why the gap exists

Building genuinely verified content, a real Authority Graph, checked statutory citations, current procedural deadlines, for nine legal systems requires primary-source research per proposition, which this build did not perform beyond the structural level above. Doing that research and shipping it as `EXPERIMENTAL` or fabricated would violate the system's own hard-failure rules (`docs/SPEC_FULL_TEXT.md`, Part CLXVII). Shipping it undone, and saying so here, is the alternative that keeps the rule intact.

## Roadmap to the next honest milestone

1. Pick one matter type in one jurisdiction (e.g. unfair-dismissal in England & Wales, or a contract dispute in US Federal via CourtListener) and run it fully through `legal-work` → `legal-research` → `legal-verify` → a real quality-gate pass, with every authority actually checked against a primary source.
2. Populate `benchmarks/hallucination-traps.md` with enough seeded cases to be a meaningful regression test, and actually run the adversarial/jurisdiction/temporal suites once they exist.
3. Only then start widening jurisdiction depth, one verified proposition at a time, per `docs/SPEC_FULL_TEXT.md` Part CLX (jurisdiction pack contribution requirements).
